# ダイアログ・UI

> ステータス: 🟡 表示の仕組みはあり（系統が2つ）／新方向への統合はこれから ／ [← 目次へ](../README.md)

## これは何？

**メッセージや選択肢を画面に出す**ための部品です。いま、これには **2つの系統**があります。

1. **歩行サンドボックスの独自実装**（新方向・1280×720）… 実際に動いているのはこちら
2. **旧UI部品**（`DialogBox` など・320×180前提）… 旧ゲーム用。新方向では未使用

> 将来この2つを新方向に一本化していく、というのが大きな方針です。

## 実装済み

### サンドボックス側（新方向・実際に動く）

- `WalkSandboxScene` 内に独自実装：`openMessage` / `openChoice` / `drawChoice`。
- メッセージ＝スペースで送る。選択肢＝↑↓で選び、スペースで決定（返事 `reply` があれば追加表示）。
- 枠は[素材システム](assets.md)の `makeWindow`（ナインスライス）で描画。枠絵が無ければ半透明四角に自動フォールバック。
- 詳しい操作は[イベント](events.md)を参照。

### 旧UI部品（320×180前提・参考資産）

| 部品 | 役割 |
| --- | --- |
| `DialogBox` | メッセージ送り（Space）＋選択肢（右上にメニュー） |
| `VerticalMenu` | 縦並びの選択メニュー（↑↓選択・Space決定・Qキャンセル） |
| `uiHelpers` | テキスト・パネル生成などの共通ヘルパー |
| `CatchableDetailView` | 図鑑・釣果で使う収集物の詳細表示（イラスト・名前・★レア度・説明） |
| `GameScene`（基底） | モーダル（重ねて出す窓）の管理 |

- これらは**画面サイズ320×180を前提の固定値**で書かれており、そのままでは1280×720に合いません。
- 入力は旧仕様：Space送り・↑↓選択・Qキャンセル・E図鑑。

## 検討したい

- **1280×720への作り直し**：メッセージ枠の高さ・選択肢の位置・フォントサイズをどう決めるか（固定値を作り直すか、相対値にするか）。
- **選択肢の見せ方**：右上固定／中央／全画面メニューなど、どのレイアウトにするか。
- **旧UI部品の再利用 or 新規**：ソート・詳細表示などのロジックを引き継ぐか、ゼロから作るか。
- **操作体系**：新方向でも Space/↑↓/Q を踏襲するか（ゲームパッド対応も含めて）。
