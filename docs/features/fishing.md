# 釣りゲーム

> ステータス: 🟡 ステージ1（試作）が1280×720で動く ／ [← 目次へ](../README.md)

## これは何？

このゲームの核になる**釣りのミニゲーム**です。共通コンセプトの1つ（釣りゲームである）。
新方向（1280×720）では**「ロケットで星に着陸し、その星で釣れる収集物を釣り尽くす」**という
ステージ制で作り直し中。旧プロトで手ざわりまで作り込んだ資産（テンポ・メーター・難易度）は
そのまま引き継ぎつつ、抽選方式だけステージ制に合わせて変えている（下記）。

> 手ざわりの調整履歴は [`tuning-log.md`](../tuning-log.md) に全テイク残っています（ゲーム性を変えたら必ず追記）。

## 新方向の実装（ステージ1・試作）

`SandboxFishingScene`（1280×720）として動く試作。歩行サンドボックスの釣りポイント
（「つりする？」→「うん。」）から入れる。

- **ステージ＝主人公が「星」と呼ぶ場所**：文字通りの惑星ではなく、日常のちょっと変な場所
  （ステージ1＝「ファミレスのポール看板の上」）。ロケットで着陸し、探索完了で次の星へ。
  同じ星には戻らない想定（[`concept.md`](../concept.md) 参照）。
- **1ステージ＝収集物5種、緩いテーマで括る**：ステージ1は食べ物テーマ
  （目玉焼き＝普通／イカ大根＝ちょっとレア／飲食店営業許可証＝レア／
  かなしい手紙＝凄いレア（一度きり）／ハム＝伝説）。
- **レア度は5段階（`StageRarity`）**：普通／ちょっとレア／レア／凄いレア／伝説。
  レア度ごとに `stageDifficulty.ts` の `STAGE_DIFFICULTY_CONFIGS` から釣りパラメータ
  （フッキング猶予・メーター必要成功数・Good可否・食いつきのフェイント＝ピクン回数の範囲・
  メーターの速さ）を引く。レア度が高いほど全パラメータが厳しくなる
  （[tuning-log take20](../tuning-log.md#take20--レア度5段階重複あり抽選レア度連動の難易度ロケットでの名付けフロー2026-07-15) 参照）。
- **失敗するほど、少しずつ難易度が緩む救済もある**（`getRelievedConfig`）：同じレア度への
  挑戦に失敗（早合わせ・フッキング失敗・メーターMiss）した回数をレア度ごとに数える。
  **5回目までの失敗は今まで通りの厳しさのまま**で、**6回目の失敗から、1回失敗するごとに**
  食いつきの猶予とメーターの速さだけを少しずつ緩める。ただしひとつ下のレア度より
  必ず厳しい状態を保つ歯止めがあり、際限なく簡単にはならない
  （[tuning-log take24](../tuning-log.md#take24--ハムの緩和を5回目までは変化なし6回目から1回ごとに変更ロケットに図鑑閲覧を追加2026-07-16) 参照）。
- **抽選は基本「重複あり」**：`StageCatalog.rollForStage()` が、既に釣った種も含めて
  毎回全種類から重み付き抽選する（同じ種が何度も釣れてよい）。
  ただし `uniqueCatch: true` の種（凄いレア以上に付けられる。ステージ1では「かなしい手紙」）
  だけは、一度釣ったら候補から除外され、そのステージでは二度と出ない。
  出現率の低い種が運悪くなかなか出ない問題には、粘る（キャストを重ねる）ほど
  未発見の種の重みが緩やかに上がる救済を入れている（確定保証ではない、上限あり）。
  全種を最低1回ずつ釣って図鑑が埋まると探索完了。
- **「大トリ」ルール**：そのステージで最もレアな種（ステージ1ではハム）は、それ以外の
  種を1種でも発見していない間は**絶対に**候補に入らない（確率0%）。それ以外を全部
  発見し終えると大トリも低い重みで候補に加わるが、**確定100%ではない**。他の種も
  引き続き候補に残るため、すぐには出ないこともある。その状態で粘る（キャストを
  重ねる）ほど、大トリの重みだけが専用の救済で上がっていく（上限あり、100%には
  ならない）。「他を集め終えるまでは絶対に出ない／集め終えたら低確率から本気で
  待つターンに入る」という2段階の体験にするための特別ルール
  （[tuning-log take25](../tuning-log.md#take25--ハムは他4種を発見し終えるまで出現しない大トリルールを追加ロケットの位置を確定2026-07-16) /
  [take26](../tuning-log.md#take26--大トリハムは確実な100ではなく低確率スタート専用救済に変更2026-07-16)）。
- **探索完了は自動遷移しない**：完了すると「探索を終えた」メッセージが出るだけで、
  ベランダには自動で戻らない（スペースで戻る操作は必要）。
- **ロケットはいつでも調べられる場所**：ベランダに置いた**ロケット**（調べる）を調べると
  「図鑑を見る」がいつでも選べる。探索完了済みなら、それに加えて
  「この星に名前をつけて出発する」も選べる（[図鑑](encyclopedia.md) 参照）。
- **星の名前は自由形式で入力**：名付けを選ぶと `window.prompt()` でその場で好きな文字を
  打って入力できる（空欄・キャンセルなら「名前をつけるのをやめた。」で終わる）。
  探索完了状態・発見済みアイテムはどちらも `localStorage` に保存し、釣りシーンと
  ベランダのシーンをまたいでも判定・表示できる。
- **見た目は仮素材**（四角・テキストのみ）。演出・効果音は次の段階。
- **釣果演出はシンプルな一言のみ**：釣れると「○○を つかまえた！」の一言フラッシュ
  （スペースで続ける）で統一。HIT表記→シルエット→選択肢というバトルコマンド風の演出は
  目玉焼きで試作したが、「イカ大根などと同様の仕様で大丈夫」との判断でいったん外した
  （[tuning-log take21](../tuning-log.md#take21--目玉焼きの選択肢演出を削除星の名前を自由形式入力に2026-07-15)）。
- **選択肢システム自体はコードとして残っている**：`PostCatchChoice` 型・`runCatchSequence`・
  際どい選択肢（`risky`）→ミニゲーム→成功で選択肢に戻る／失敗で逃げられる、という仕組みは
  そのまま。`POST_CATCH_CHOICES` に1件足せば、その種にまた選択肢が復活する
  （元ネタは [tuning-log take16](../tuning-log.md#take16--釣果演出hit→シルエット→正体→選択肢を追加2026-07-14) /
  [take17](../tuning-log.md#take17--際どい選択肢→ミニゲーム→成功で選択肢に戻る失敗で逃げられる2026-07-14)）。
- **文章はスペースで続ける**：釣果・警告・結果などの文章は自動で消えず、スペースを
  押すまで表示され続ける（[tuning-log take18](../tuning-log.md#take18--釣果演出の文章をスペース待ちに自動で消えないように2026-07-14)）。
- **フッキングとメーター開始は別アクション**：フッキングは1回押すだけの判定（変更なし）。
  成功後はいったん「長押し待ち」になり、既定300ms以上スペースを押し続けて初めてメーターが
  始まる（[tuning-log take19](../tuning-log.md#take19--フッキングとメーター開始を分離1回押す→長押しでメーター開始2026-07-14)）。

## 実装状況（＝旧プロトの資産。テンポ・メーターの"ロジック"はここから引き継いでいる）

> ※ レア度・難易度パラメータ・抽選方式は新方向で独自の仕組み（`StageRarity` / `stageDifficulty.ts` /
> `StageCatalog.rollForStage`）に置き換わっている。ここから引き継いでいるのは、
> あくまで釣りの流れ（間→ピクン→フッキング→メーター）とメーターの計算ロジックそのもの。

### 釣りの流れ（take2 で完成）

```
投入 →[2500–5000ms の「間」]→ ピクン0–3回＋沈み込み
   → フッキング(猶予は難易度依存) → メーター(必要成功数ぶん) → 釣果
```

- **早合わせ失敗ペナルティ**：待機中にスペースを押すと「あわてた！」で仕切り直し。
- **押しっぱなし引き継ぎ**：フッキング→メーターでスペースを押したまま繋がる（一体感）。

### メーター（`GaugeMeterGame`）

- スペースを押し続けるとゲージが左→右へ伸び、**離した位置**で判定。
- 速度 `FILL_MS = 2000ms`。判定ゾーン：Perfect `[.33,.67)` / Good `[.13,.33)`＋`[.67,.87)` / Miss 両端（やさしめ）。
- **差し替え可能設計**：`MeterGame` インターフェース（`start(): Promise<'perfect'|'good'|'miss'>`）＋ `createMeterGame` ファクトリ。釣り本体を変えずにミニゲームだけ別実装に差し替えられる。

### 難易度（`difficulty.ts`・旧プロト専用。原則変更しない）

| 難易度 | フッキング猶予 | メーター必要成功数 | Good可否 |
| --- | --- | --- | --- |
| EASY | 600ms | 1回 | 可 |
| NORMAL | 500ms | 2回 | 可 |
| HARD | 350ms | 4回 | 不可 |
| LEGEND | 250ms | 8回 | 不可 |

新方向（ステージ制）はこれとは別の `stageDifficulty.ts`（`StageRarity` 5段階、
フェイント回数・メーター速度も持つ）を使う。上の「新方向の実装」を参照。

### 収集物データ（`catchables.ts`）

- 全 **14種**。各データ＝ `id` / `encyclopediaNumber` / `name` / `description` / `rarity(1–5)` / `difficulty` / `imageKey`。
- レア度分布：1（4種EASY）/ 2（3種NORMAL）/ 3（2種）/ 4（2種HARD）/ 5（3種LEGEND）。
- レア度（`rarity`）と難易度（`difficulty`）は連動：**レア度が高い魚ほど出にくく、かつ釣るのも難しい**。
- 新方向（ステージ制）は `stageCatchables.ts`（ステージごとに作り変え、`StageCatchable` 型）を使う。

### 抽選（`Catalog.ts`）＝どの魚が釣れるか（旧プロト専用）

釣りをした瞬間に「どの収集物が釣れるか」をランダムで決める仕組み。レア度による出現確率の重み付けを担う。

- `Catalog.roll()`：重み `= (最大レア度 + 1 - rarity)²`。**レア度が高いほど二次関数的に出にくい**。
  - 例（最大レア度5のとき）：レア度1＝重み25 ／ レア度3＝重み9 ／ レア度5＝重み1（レア度1はレア度5の25倍出やすい）。
- 乱数は差し替え可能（テスト用に引数で渡せる）。
- ※ 現状この重み付けは**釣りの状態遷移にはまだ未接続**（旧プロトのまま。新方向は別途 `StageCatalog` で接続済み）。

### 状態遷移（`FishingScene`）

- 5フェーズ（watch / hookWindow / hit / transition / ended）で制御。猶予切れで魚が逃げる。
- 釣り上げ時に図鑑登録・発見フラグ・ローカル保存を呼ぶ（[図鑑](encyclopedia.md) / [セーブ](save.md)）。

## 検討したい

- **見た目・演出**：浮き・竿・プレイヤーは仮の四角のまま。低コストなアニメ・効果音を
  惜しみなく盛り込みたいという方針あり（[concept.md](../concept.md)）。ステージのテーマに合わせた
  演出替え（例：食べ物テーマなら「釣り＝料理してる」風に見せる、ジュージュー音を足す）も案として出ている。
- **メーターの代替案**：ファクトリ設計のおかげで差し替え可能。クリック式など次の候補を作るか。
- **名付けの見た目**：入力自体は `window.prompt()`（ブラウザ標準のダイアログ）で動く。
  ゲーム画面に馴染む見た目の入力欄にしたいかは今後の検討。
- **ステージ2以降・「次の星へ」の遷移**：今はステージ1しか無い。名付け後にロケットで
  飛び立つ演出、マップ切り替えの作り（[マップ管理](maps.md)）はこれから。
- **レア度連動パラメータの数値調整**：フェイント回数・メーター速度・救済の強さは
  叩き台の初期値。伝説（ハム）は「難しすぎる」の報告を受けて何度か調整し、現在は
  「初めて挑戦するときの厳しさ（take20の値）は変えず、6回目の失敗から1回ごとに
  少しずつ緩める」形に落ち着いている
  （[tuning-log take23](../tuning-log.md#take23--ハムの基本難易度をtake20の値に戻し救済は基準値の上にかぶせる形に2026-07-16) /
  [take24](../tuning-log.md#take24--ハムの緩和を5回目までは変化なし6回目から1回ごとに変更ロケットに図鑑閲覧を追加2026-07-16)）。
  他のレア度も含め、実際に触った手ざわりで引き続き調整する。
- **図鑑・セーブとの接続**：発見済みアイテム・探索完了状態は `localStorage` に保存
  するようになった（[図鑑](encyclopedia.md) 参照）。ただし「本物のセーブ」（他の進捗と
  まとめて扱う仕組み）とどう統合するかは方針決め待ち（[セーブ](save.md)）。
- **ゲーム内チューニングエディタ**：パラメータを画面上で試せる仕組みが要るか。
