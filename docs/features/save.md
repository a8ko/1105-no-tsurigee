# セーブ（ローカル保存）

> ステータス: ⬜ 本編セーブは未着手（資産あり）／サンドボックスの自動保存は実装済み ／ [← 目次へ](../README.md)

## これは何？

進行状況を**ブラウザの中（localStorage）に自動で残す**仕組みです。共通コンセプトの1つ（ローカル保存）。
いまは2つの保存が別々に動いています。

1. **サンドボックスの編集データ**（壁・スタート位置・イベント）… 新方向で実働
2. **旧プロトのゲームセーブ**（発見済み収集物・現在地）… 本編で作り直す資産

## 実装状況

### サンドボックスの自動保存（新方向・実働）

- マップごとに分けて保存（[マップ管理](maps.md)）：
  - 壁：`tsurigee:sandbox:collision:v2:{マップID}`
  - スタート位置：`tsurigee:sandbox:spawn:v2:{マップID}`
  - イベント：`tsurigee:sandbox:events:v2:{マップID}`
- 編集のたびに自動保存。旧 v1 キー（1マップ時代）は初回だけ引き継ぎ。
- これは**エディタの作業データ**で、下のゲームセーブとは保存領域が別です（互換なし）。

### 旧プロトのゲームセーブ（＝引き継ぐ資産）

- 保存キー：`tsurigee:save:v1`。
- `SaveData` の形：`discoveredItems`（発見済みID配列）/ `currentMap` / `playerX` / `playerY`。
- `SaveManager`：`load` / `save` / `clear` / `createNew`。壊れたデータは `normalize` で補正（未知マップ→スタート、無効IDは除去）。
- `GameState`：実行中の状態を持つシングルトン。`discover(id)`（発見して自動保存）・`setLocation(...)` など、状態が変わると自動で保存。

## 検討したい

- **保存を分けるか統一するか**：
  - 案A（分離）：サンドボックス用 `tsurigee:sandbox:*` と本編用 `tsurigee:game:*` を完全に分ける
  - 案B（統一）：`tsurigee:save:v2` などに寄せ、マップID＋セーブスロットへ拡張
  - 要件未確定の今は、無理に統一せず柔軟性を保つのが無難。
- **保存する中身**：複数マップ・イベント進行・所持品などを足すときのスキーマ更新（v2, v3…）の方針。
- **プレイヤー位置**：複数マップ時、「どのマップのどこ」を保存する形に。
